# ADR-023: KERI recovery discovery, structured witness receipts, and explicit room secret

**Date:** 2026-05-25
**Status:** Accepted
**Decision makers:** user + Codex adversarial review (release-readiness pass)

> **Superseded in part (2026-07-31, ADR-037).** Decision 3, its room-secret
> leak fix and rotation, and its private-broadcast vector consequences are
> retired. Decisions 1, 2, and 4—KEL discovery, structured witness receipts,
> and relay-level interoperability wording—remain accepted.

## Context

An adversarial release-readiness review of the 0.x spec — preparing it
for open feedback from the Nostr and cryptography communities — surfaced
five high-severity findings. Three of them require load-bearing wire and
algorithm changes resolved here; the other two (a private-broadcast
relay leak and an overstated vanilla-Nostr interop claim) are spec-text
fixes that fall out of these decisions or are pure wording and need no
new record.

1. **KERI recovery rotations are undiscoverable by the specified relay
   query (§3.5.2–§3.5.3).** A `none`-strategy rotation (recovery after
   cold-root loss) is authored — and signed — by the *prior epoch key*,
   not the cold root. But the verifier discovered the key event log
   (KEL) by querying for events whose author is the cold-root pubkey. A
   relay-only verifier therefore never sees the very recovery rotations
   the `none` strategy exists to carry: the KEL stalls or diverges
   depending on whether a client also happened to see a Matrix mirror.
   This defeats the design goal that the relay-published KEL is
   self-sufficient and the homeserver is an untrusted, blind router.

2. **Witness attestations were not a conventionally specified wire
   format (§3.5.2).** `content` was described as "concatenated witness
   attestation signatures, base64-encoded," with no defined per-witness
   signed preimage, signature length, ordering, scheme tagging, or
   witness→signature mapping. Threshold and fork verification were not
   independently implementable.

3. **Room-key wrapping depended on undefined Megolm key material
   (§6.7.4, §6.10).** The HKDF input keying material was "the Megolm
   outbound session key (32 bytes)." Megolm exposes no such stable,
   portable 32-byte room secret: its ratchet advances on every message
   and exported session bytes depend on the ratchet index, so two
   members deriving "from the Megolm session" can arrive at different
   keys, and the relay-visible `megolm_session_id` does not uniquely
   select the bytes a client must use. ADR-005 explicitly considered and
   rejected an independent room secret as "over-engineered"; that
   judgment is reversed here on cryptographic-soundness grounds.

## Decision

### 1. KEL discovery by relay-indexed cold-root tag (+ chain fallback)

- Every inception (`kind:31002`) and rotation (`kind:31003`) event MUST
  carry a `["p", "<cold-root pubkey hex>"]` tag equal to the persona's
  cold root — never the event author. This reuses the convention the
  existing `kind:31008` social-vouch already follows.
- The canonical KEL discovery query is by that relay-indexed tag, not by
  author: `{"kinds":[31002,31003], "#p":["<cold-root>"]}`. This returns
  `none` rotations (authored by the prior epoch key) in the same single
  query.
- Verifiers SHOULD additionally **chain-discover** as a defensive
  secondary path: after accepting each event they learn its `epoch_key`
  and issue follow-up `authors` queries for the accepted epoch keys, to
  recover any `none` rotation a relay omitted from the `#p` result.
- The open `#p` query may return unrelated or forged events; the
  existing signature / `prior_digest` / threshold / first-seen
  verification discards them, so the wider query introduces no new trust
  surface.

### 2. Structured witness receipts

- The rotation `content` MUST be a compact-JSON array of receipt objects
  `{"witness_id","scheme","sig"}`, ordered ascending by `witness_id`,
  with at most one counted receipt per `witness_id`.
- `scheme` ∈ `"bip340" | "did:key" | "atproto"` selects the verification
  algorithm and public key for `witness_id`. `sig` is the lowercase-hex
  encoding of the raw signature bytes for every scheme.
- **Signed value.** Every witness signs the same 32-byte
  `witness_digest` = SHA-256 of the rotation event's canonical NIP-01
  serialization computed **with `content` set to `""`**. Empty `content`
  breaks the circularity (the receipts live in `content`); the event
  `id` and the next event's `prior_digest` still commit to the full
  receipt array.

### 3. Explicit Heterodyne room secret (supersedes ADR-005 key source)

- Each `private_broadcast` / `private_discussion` room has a uniformly
  random 32-byte **Heterodyne room secret**, generated by the publisher
  and distributed in an `m.heterodyne.room_secret.v1` **Megolm-encrypted
  state event** whose decrypted content carries an opaque `key_id`, the
  `secret`, and `created_at`.
- `room_key` / `post_key` / `index_key` are HKDF-SHA256 over this
  `room_secret` (salt = room id, `info` labels unchanged). The Megolm
  outbound session key is no longer used as HKDF input.
- Relay-visible tags become `["heterodyne_wrap","room_key.v2"]` and
  `["key_id", "<opaque id>"]`. `v1` (Megolm-derived,
  `megolm_session_id`) is retired and MUST NOT be honored.
- **Private-broadcast leak fix (finding 4).** `private_broadcast` posts
  MUST NOT carry cleartext `matrix_room` or `megolm_session_id` tags;
  room/session details live in the encrypted payload and the
  Matrix-advertised descriptor, matching the private-index treatment
  §6.7.4 already used. A relay observer learns that *a* Heterodyne
  room-wrapped post was published and its timing, but not which room.
- **Rotation.** On member removal, the publisher MUST mint a new room
  secret (fresh `key_id`) and MUST also rotate Megolm (so the new secret
  is not encrypted to the departed member). Access control is possession
  of the room secret for a `key_id`, gated transitively by the Megolm
  session that encrypts `m.heterodyne.room_secret.v1`.

### 4. Interop claim downgraded (finding 5, no separate mechanism)

§11.2 is reworded from "no special support needed to read" to
**relay-level NIP-01 compatibility only** — the bytes are valid Nostr
events any relay stores and any client can verify if it holds them —
explicitly distinct from social-graph discovery (follows, author
queries, replies, reputation keyed to the npub), which does not resolve
to epoch-key-signed content without replaying the KEL.

## Consequences

- §3.5.1/§3.5.2 schemas gain a mandatory `p` tag; §3.5.3 step 1 queries
  by `#p` and adds the chain-discovery fallback.
- §3.5.2 defines the witness-receipt array and the content-empty
  `witness_digest`; §3.5.3 step 3c verifies receipts.
- §6.7.4 defines `m.heterodyne.room_secret.v1` and re-bases all wrap-key
  derivation on the room secret; §6.10 follows and drops the leaky
  cleartext tags. `heterodyne_wrap` bumps to `room_key.v2`.
- ADR-005 and ADR-017 wire details updated in place; ADR-005's
  Megolm-derived key-source rationale is preserved as historical record
  and marked superseded here.
- New test vectors needed (extends the still-empty §11 conformance
  floor, the review's medium finding): `#p` discovery incl. a `none`
  recovery rotation; committed/none/fork receipt verification;
  content-empty `witness_digest`; room-secret HKDF + NIP-44 wrap;
  private-broadcast decrypt with no room id on the wire.

## Alternatives Considered

- **KEL discovery — verifier chain-discovers by author only (no tag):**
  no wire change, but needs multiple query rounds and a defined fan-out
  loop, and is brittle if an intermediate epoch key's rotation is missing
  from a relay. Adopted as the *secondary* path, not the primary one.
- **Witness format — fully specify the byte concatenation:** smaller
  change, but does not cleanly support mixed witness types (Nostr +
  did:key + ATProto) in one rotation. Rejected for the self-describing
  receipt array.
- **Room key — pin exact Megolm export bytes + session selector:** keeps
  the Megolm coupling ADR-005 valued, but remains fragile (ratchet
  advances per message) and still requires the relay-leak fix
  separately. Rejected for the explicit room secret.
