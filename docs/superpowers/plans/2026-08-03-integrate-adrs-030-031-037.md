# ADR-030, ADR-031, and ADR-037 Integration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate ADR-030 and ADR-031 completely, reconcile ADR-030 with the
later Comms/Control decisions, and integrate the independently mergeable
ADR-037 corrections without publishing an invalid partial registry revision 4.

**Architecture:** Core owns the common delegation, KEL, typed-key, node-advert,
and breadcrumb verification primitives. Comms owns DR authentication,
enrollment context, generic encrypted carriers, credential state, and claim/
OIDC behavior. Control owns enrollment, grants, RPC, MCP, replay, and agentic
semantics while using only Comms carriers. Social owns vanilla following and
advisory breadcrumb presentation. Registry revision 4 remains an atomic
ADR-037/ADR-038 artifact and is not published without the complete ADR-038
schema/feature batch required by accepted ADR-037.

**Tech Stack:** Markdown normative specifications; JSON Schema draft-07;
TypeScript 5.9; Vitest; `@noble/*`; Nostr NIP-01/BIP-340;
`nostr-double-ratchet@0.0.138`; generated JSON conformance vectors.

## Global Constraints

- The protocol family remains `0.x`; signed bytes and identifiers may change
  before 1.0, but release records preserve exact artifact digests.
- The normative dependency DAG remains `Core <- Comms <- Control` and
  `Core <- Comms <- Social`; Social never depends on Control.
- Control owns no transport or wire stamp. All Control session payloads are
  Comms-owned encrypted inner rumors.
- Automated agents never receive or directly exercise persona, epoch, NID,
  human-device, or agent-role private keys.
- ADR-035 ingress-relay affinity and restart-safe payload-digest binding
  supersede ADR-030's older `(device key, request id, method)` replay wording.
- Relay observation of a session-device delegation is provisional. Enrollment
  becomes final only through Core repository finality.
- ADR-038 recovery approvals and transfers do not open general Control and are
  not ADR-030 enrollment tokens.
- Revision 4 must not be emitted with placeholder, wildcard, omitted, or
  unbound ADR-038 allocations.
