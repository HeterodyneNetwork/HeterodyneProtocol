# Rolling Pre-1.0 Vector Snapshot Implementation Plan

> **Execution:** Use `superpowers:subagent-driven-development`. Each task gets a fresh implementer, then a specification review and a quality review. Apply `superpowers:test-driven-development` within every behavior-changing task and `superpowers:verification-before-completion` before acceptance.

**Spec:** `docs/superpowers/specs/2026-08-21-rolling-vector-snapshot-design.md`

**Goal:** Decouple ordinary pre-1.0 specification edits from vector regeneration while retaining one reproducible, exact-commit-pinned conformance snapshot in this repository.

**Architecture:** Split validation into a current-HEAD draft lane and a pinned-history snapshot lane. The snapshot manifest binds exact generated bytes to source commit `2ef40a6d6304f8f5e6162f84c12b7b03a42a3c43`; source-commit generator behavior is normalized by a snapshot-commit packager that may change only envelope metadata and projections. The standalone conformance package reads specification authority from the source checkout and vector bytes from the snapshot checkout.

**Technology:** Node 22, TypeScript, Vitest, AJV, Git object/worktree commands, POSIX shell, GitHub Actions, Radicle CI.

**Bootstrap invariant:** The stable source commit authors 482 vector files. The migrated snapshot has the same vector IDs and parsed `input`, `expected_output`, `direction`, and `profile` values, removes per-vector `spec_version`, and uses document-qualified `spec_refs`.

## Global constraints

- The full source SHA is exactly `2ef40a6d6304f8f5e6162f84c12b7b03a42a3c43`; accept no abbreviated or symbolic revision at a Git boundary.
- `snapshot.json` and every generated JSON file use canonical two-space JSON plus one LF. Artifact digests cover exact bytes.
- The snapshot inventory includes every consumed snapshot datum: vector documents, `fixtures.json`, packaged vector schema, reason-code projections, and coverage projections. It excludes only documentation, source code, lockfiles/dependencies, checker contracts, and `snapshot.json` itself.
- Source root owns the five specification documents, registry, protocol schemas, source generator, and authoring inputs. Snapshot root owns vectors, fixtures, packaged vector-envelope schema, reason/coverage projections, and manifest. Snapshot-commit root owns the behavior-neutral packager and its lockfile.
- A packager may remove `spec_version`, set `vector_schema_version`, qualify `spec_refs`, and rebuild deterministic projections. It may not add checker declarations or alter vector ID, `input`, `expected_output`, direction, or profile.
- The bootstrap executes zero declared reference-checker cases; static gates still run, and runtime/report output makes the zero count explicit.
- Derived `snapshot_commit` appears only in runtime output. Committed reports/baselines use `source_commit` plus snapshot artifact-set digest.
- No generator/conformance source imports in either direction. The generator's snapshot-check command owns temporary orchestration and invokes the conformance CLI by process with explicit roots.
- All temporary paths are internally created with `mkdtemp`; preflight Git trees reject unsafe paths, symlinks, submodules, and special modes; cleanup never accepts a caller-owned destination.
- Normal checks are read-only. Authoring stages a complete sibling tree, validates it, then swaps with rollback. No command tags, releases, deploys, merges, or publishes.
